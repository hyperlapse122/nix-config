### F1 — Activation text does not prove activation executes

Locations: `tests/claude.nix:198`, `tests/codex-settings.nix:102`, `tests/gemini.nix:97`, `tests/tokscale.nix:174`, and the harness extraction in `tests/agent-plugins.nix:218`.

Contract: activation invokes the declared merger/synchronizer on the correct user file, and a refusal fails activation. An `echo` before a command preserves the helper path, flags, declaration, ordering metadata, and the absence of the enumerated suppression strings. All of these tests' string predicates accept it. Tokscale runs the extracted merger separately, and agent-plugins reconstructs and runs the Pi invocation separately; those executions do not establish that activation runs it. They also accept a dead branch containing the correct command. This is a proof gap, not a claim the current activation is broken.

Strongest remaining proof: `tests/test_agent_settings.py` owns merger semantics; `tests/test_agent_plugin_sync.py` owns adapter sequencing/rollback; `tests/antigravity-plugin-install.nix` owns real agy compatibility. None executes these actual activation blocks. `tests/t3code-traits.nix:728` already executes activation with a recording stub, verifies arguments, and runs a failing stub. `tests/pi.nix:141` executes a substituted failing merger, which catches an echo but does not replace the missing invocation proof in the named checks.

Repair: execute each actual activation block in a scratch home with the absolute helper replaced by a recording/failing stub, checking recorded argument boundaries and exit status. For the settings blocks, also redirect the actual destination and assert the merged file from a divergent seed. Keep the independent declaration values, package identity, DAG placement, no-store-link, secret, and pin contracts. Do not run real signed-in CLIs. For agentPlugins, exercise the whole script across all harness rows with stubs; do not reconstruct commands from grepped arguments.

History: Claude's user merge originated in `e9a1f2b`; Antigravity's merge in `31c415a`; Codex restoration added `tests/codex-settings.nix` in `316f7e0`; Tokscale declarations in `1468a7f`; plugin sync in `cea4236`, with the config check expanded in `7159a1c`. The later activation-execution fix `4dbf84b` corrected this pattern for Darwin Pi, but the listed checks retain the older pattern. Applicable learning: `activation-step-grep-check-passes-an-echo-only-step.md`.

Evidence: under `/tmp/agents-audit-njvsoumr`, unmodified copies of `tests/gemini.nix` and `tests/lib/configurations.nix` were instantiated with Darwin packages and two synthetic production/bootstrap config entries. The control check built successfully. The same check built successfully when the activation body became `echo <helper> --settings ... --declared ...`. No test source was altered. This is an exact check-logic replay with synthetic inputs, not a production Linux check build. Source inspection establishes the corresponding gap in the other listed checks; those full builders were not run locally. Validation after repair: the named x86_64-linux checks, with echo/dead-branch/failing-helper mutations, must fail with their own messages, followed by clean control builds.

### F2 — Gemini memory setting can disappear while the check stays green

Location: `tests/gemini.nix:57` (read of `home.file.".gemini/settings.json".text`).

Keeper: retain this independent configuration contract in `gemini.nix`. Generic merger tests do not cover a store-delivered Gemini file; the current Darwin and non-NixOS checks do not read its delivered contents. Repair by reading `.gemini/settings.json` from `home-files` for every relevant user, with explicit missing/disabled/retargeted controls. Keep Antigravity's separate mutable-file merge contract.

History: `git blame` attributes the option-text read to `926c002` (2026-09-21); later changes, including the activation migration and host iteration, preserved it. The project learning `nix-check-reads-option-value-not-materialized-output.md` describes this exact proxy failure.

Evidence: the same isolated native replay used for F1 built successfully with `enable = false`, while its text still declared autoMemory false. The wrong-value control (autoMemory true) failed the native replay with `Expected experimental.autoMemory to be false`, confirming that the value predicate is live while the disabled-file mutant survives. No actual Home Manager generation was activated. Validation after repair: disabled, retargeted, and missing-file mutations must fail at the materialized delivery guard.
