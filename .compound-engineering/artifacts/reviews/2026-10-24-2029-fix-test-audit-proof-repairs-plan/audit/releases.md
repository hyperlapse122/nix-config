## Findings and layer plan

### F1 — failed-fetch payload suppression is untested

`tests/test_agent_plugin_release.py:124` only checks status and an error substring. Its fetch fixture exits at lines 24-25 before producing any body, and the test never asserts that a sentinel is absent. A regression printing the failed command's stdout/stderr therefore stays green. Keep this security contract at the release CLI boundary; `test_malformed_payload_does_not_echo_it` at line 117 guards a different, successful-fetch/invalid-JSON path and does not replace it. History: both declarations arrived in `cea4236` with the resolver. Production caller: updater's plugin-tag resolution, `.github/workflows/update-dependencies.yml:52`, via `packages/agent-tools.nix:61` and `flake.nix:150`. Repair the stub to emit a distinctive failed-response sentinel, and assert its absence from both streams. In a standalone `/tmp` copy, original test passed on control and on an owner mutant that prints `proc.stdout` and `proc.stderr` in the nonzero-return branch. The repaired test failed that mutant and passed the original owner (exit 1 and 0). No production seam is needed.

### F2 — duplicate cron minutes count as two executions

`tests/update-dependencies-reconcile.sh:294` checks array length, not distinct minute values. Replacing `7,37` with `7,7` in the workflow gives one effective minute per hour, but the entire check passes with GNU tools and prints that it fires twice hourly. Keeper is this workflow schedule check; no release resolver or push-order test covers scheduling. History: `82e2e7a` introduced the twice-hourly schedule and this suite; subsequent edits preserve the length-only condition. Repair by parsing numeric minutes, requiring two distinct minutes (and, for the documented every-30-minutes contract, a difference of 30); retain the off-hour and full-hour/day coverage checks. Control and duplicate-minute mutant both exited 0 under the same GNU-tool environment. This is assertion repair, not schedule removal.

## Owner boundaries, overlap and CI routing

Each resolver is a separate executable owned by `scripts/<release-name>`. They are packaged in `packages/agent-tools.nix`, exported as flake packages, and invoked by `update-dependencies.yml`; emitted pins feed the corresponding package derivations. Similar version/digest cases across resolvers are retained: separate parsers, manifests, asset names, supported systems, serialization and downgrade behavior can regress independently. Fetch environment overrides are existing offline transport boundaries, not grounds alone to delete the tests. Package consumption/build checks do not exercise malformed upstream responses and cannot replace release checks.

The Android resolver is Ruby with Nokogiri and vendored nixpkgs androidenv XML conversion. Its flake check drives the packaged helper (`flake.nix:769`), protecting interpreter dependencies as well as the CLI contract. `android-sdk-repo-parity` independently compares the committed pin to nixpkgs' own repo.json; renderer examples cannot replace upstream parity. Parity has nonempty comparison and revision-shape guards. SDK platform, NDK, CMake, ABI, license, emulator-compatibility and pin-preservation contracts remain separate.

Catalog snapshots feed `pi-declarations.py` through `pi-declarations.nix` and `pi.nix`. OpenRouter row validation and Synthetic row validation remain separate provider contracts even though JSON I/O, shrink-floor and bearer transport share `catalog_snapshot.py`. Retain catalog boundary tests; sharing a helper alone is insufficient evidence to delete provider-specific key names, URLs, nullable fields and malformed-row retention. `model-catalogs-reconcile.sh` exercises the actual workflow run blocks with a real git remote and owner-produced push events. `synthetic-models-reconcile.sh` exercises issue delivery, using real watch results and a gh API fixture; watch classifier unit tests cannot replace issue creation/update/recovery ordering.

`tests/elf-load-segments.nix` protects deployed ELF program headers across materialized host closures, independently of resolver hashes or successful builds. `tests/check_elf_load_segments.py` performs the scan and rejects an empty scan. Do not delete it as a slow inventory test: patchelf can corrupt an executable after download without changing the pinned source identity.

All assigned Python suites are explicitly registered in `flake.nix:575-604,630-641,769-774`. The shell checks are registered at `642-660` and `1541-1584`. `synthetic-models` is registered at line 362 and ELF scanning at line 530. These checks live under the Linux checks set; `tests/check-shards.nix` routes non-host checks by sorted-name modulo into light shards, and `elf-load-segments` is explicitly in `hostClosureChecks` (line 105), hence the hosts shard. `check.yml` evaluates in flake-check and builds shards on ordinary PRs/main pushes; docs-only PRs skip those builds. The Darwin output job is separate platform/package evidence and does not substitute for these Linux checks. No missing assigned registration was found.

Applicable check learnings were consulted, especially mutation controls versus evaluation failure, materialized outputs versus options, converged fixtures, default/inventory vacuity, shell negation/nullglob/pipefail traps, explicit bare-origin HEAD, copied-worktree index isolation, prose substring negation, and macOS verification limits. Static assertions below are retained where they protect an independent configuration, package, protocol, platform, schedule or security contract.
